Code inspection		 Apollo Editor ↗ Entity aliases

Apollo covers the important batch-add fields and also edits and removes existing aliases. This is the strongest replacement candidate in the pilot.

Capabilities, gaps & evidence

Batch addition of aliases on the entity types supported by Apollo, for an editor permitted to edit those aliases.

Important capabilities
CapabilityCoverageReason
Add several aliases with a shared edit noteCoveredBoth implementations submit one edit per alias; Apollo provides multiple new rows.
Name, sort name, type, locale and primary flagCoveredApollo reads available types/locales from MusicBrainz and sends each of these fields.
Inspect individual submission resultsCoveredBoth retain per-row success or failure feedback.

What you would lose / limits

  • No important gap found in the inspected batch-add implementation. This is code-level coverage, not a live submission comparison.
  • The external shared helper was not independently reviewed; unexpected helper behavior remains a verification limit.

Switching route

Open an entity's Aliases or Add alias page with Apollo's bulk alias editor enabled. Enter the rows and review before submitting. Disable the other alias editor during the check.

Code inspection		 Mammoth ↗ Edit-note memory

Mammoth provides submitted-note history and reusable notes on MusicBrainz, but Elephant also runs on AcoustID and automatically inserts the last note into empty forms.

Capabilities, gaps & evidence

Remembering and recalling submitted MusicBrainz edit notes; AcoustID and automatic last-note prefilling are outside the covered route.

Important capabilities
CapabilityCoverageReason
Remember and recall submitted notesCoveredElephant keeps ten memories; Mammoth records deduplicated history and supports saved notes.
Automatically prefill an empty note with the last noteGapElephant explicitly calls forceValue for the last note on load; no matching default note-prefill behavior found in Mammoth.
Note memory on AcoustID edit pagesGapElephant matches acoustid.org/edit/*; Mammoth's match is MusicBrainz.

What you would lose / limits

  • Keep Elephant for AcoustID note memory or its automatic last-note prefilling.
  • The wiki description mentions dates, but this captured Elephant entry script implements note memory; do not infer date handling from that description.
  • Stored notes are not automatically migrated from Elephant's localStorage to Mammoth's GM storage.

Switching route

Copy important notes into Mammoth's Import / Export tab and compare recall behavior on MusicBrainz. Keep Elephant where its uncovered workflows matter.

  • Last-note prefilling and history save ↗

Import Bandcamp releases to MusicBrainz ↗murdos and contributorsBandcamp · Wayback Machine Partial overlapMedium confidence
Code inspection		 First Contact ↗
Apollo Editor ↗		 Release importing

First Contact seeds the main release data and Apollo handles matching. The dedicated importer has additional Bandcamp-specific behavior that prevents a general uninstall recommendation.

Capabilities, gaps & evidence

Importing ordinary public Bandcamp digital albums; archived/private pages and download/stream availability rules are material differences.

Important capabilities
CapabilityCoverageReason
Seed title, artists, tracks, lengths, date, barcode and notesCoveredBoth have Bandcamp data readers and release seeding; exact output and date/artist heuristics can differ.
Download/free-stream links and hidden download tracksGapThe dedicated importer distinguishes free downloads and hidden track counts. First Contact's inspected reader seeds purchase and conditional streaming URLs without that full decision tree.
Import from archived pages and private-stream handlingGapThe dedicated importer matches Wayback and has private-stream status/link handling; First Contact matches live album/track pages.

What you would lose / limits

  • Archived Bandcamp pages, private streams and hidden download tracks need the dedicated importer or manual handling.
  • Do not assume identical free-download, streaming, release-date or artist-credit results.
  • First Contact saves imported pages to the Internet Archive by default; turn that setting off if unwanted.

Switching route

For a public digital album, use First Contact and review the seeded metadata in Apollo. Compare source-specific URLs and hidden tracks before disabling the dedicated importer.

Evidence at assessed versions

  • Hidden tracks and availability-specific links ↗

Code inspection		 Art Station ↗
Falcon ↗		 Cover-art sourcing and upload

Art Station covers URL/file uploads, large-image sourcing and staged art editing. Enhanced Cover Art Uploads includes a broader provider set and specialist extraction paths that are not established as equivalent.

Capabilities, gaps & evidence

Source images and upload cover/event art; provider-specific extraction and external-page integration remain distinct.

Important capabilities
CapabilityCoverageReason

Specialist provider extraction, including Bandcamp track imagesGapThe external implementation fetches optional per-track Bandcamp images and Internet Archive item files; Art Station documents album-cover sourcing and generic preview fallback for unlisted sites.
Seeding from Harmony and VGMdb pagesPartialFalcon offers a Harmony route and Art Station reads seeded URLs; exact external-page buttons, selection and metadata preservation have not been established as equivalent.
